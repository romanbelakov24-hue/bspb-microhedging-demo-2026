# БСПБ Бизнес Микрохеджирование

Учебный интерактивный MVP программы «Бюджет контракта». Расчёты и ERP работают локально на вымышленных данных, состояние сохраняется в браузере. Дата учебного портфеля — 12 ноября 2026 года.

**Открыть сайт:** https://romanbelakov24-hue.github.io/bspb-microhedging-demo-2026/

**Репозиторий:** https://github.com/romanbelakov24-hue/bspb-microhedging-demo-2026

## Публикация

GitHub Pages публикует папку `docs/` из ветки `main`. Она содержит собранное статическое приложение. Сайт открывается без авторизации; кабинет хранит изменения только в браузере посетителя.

После изменения исходников:

```sh
npm run build:pages
npm test
git add src scripts public index.html package.json package-lock.json vite.config.ts tsconfig.json README.md docs
git commit -m "feat: update case demo"
git push
```

Дождитесь успешной публикации Pages в GitHub. QR использует постоянную ссылку выше, поэтому при обновлениях на том же адресе менять его не нужно.

## Запуск

Нужен Node.js 20.19+ либо 22.12+.

```sh
npm install
npm run dev
```

Открыть адрес, который напечатает Vite. Для сборки `npm run build`, для проверки доменной логики `npm test`.

## Маршрут демонстрации

1. Откройте продуктовую страницу и нажмите «Посмотреть кабинет».
2. В «Микрохеджировании» подтвердите правила покрытия 80%. На пилоте оставьте подтверждение каждой сделки. Автоматический режим — отдельная демонстрация будущей фазы 2, а не обещание готовой интеграции банка.
3. В настройках выберите 1С и загрузите демо-инвойс. Для ERP-2026-001 подготовится предложение на 20 000 CNY. В «Микрохеджировании» откройте его условия и подтвердите демо-сделку. При выбранном автоматическом режиме она исполняется в демо сразу. Повторная загрузка пропускает дубликат.
4. Откройте карточку хеджа. При курсе 13 итог на обязательстве 25 000 CNY — 305 000 ₽, при 11 — 295 000 ₽, до затрат.
5. Измените дату оплаты инвойса. Хедж сохранится со старой датой и статусом пересмотра, а в поддержке появится задача менеджеру.
6. В импорте CSV скачайте пример и загрузите его обратно. В файле есть повторная строка для проверки дедупликации. Колонки сопоставляются вручную.
7. В обмене выполните RUB/CNY. Для примера распределения CNY выберите инвойс с оплатой в CNY и сумму, которая помещается в остаток. Для рублёвого индексированного счёта используется NDF.
8. Выгрузите реестр в CSV и откройте печатную версию отчёта. В окне браузерной печати выберите PDF.
9. Перезагрузите страницу, затем сбросьте демо через настройки.

## Демонстрационные допущения

Учебные spot 11,9 и forward 12 RUB/CNY. Конверсионная комиссия 0,1% включена в вводимую сумму списания. Отдельная плата NDF равна нулю. Лимит — упрощённый предел рублёвого номинала, дневной объём задаётся в CNY. Это параметры прототипа, коммерческие условия банка согласуются отдельно.

Первый этап поэтапной политики покрывает до 30%, после отметки отгрузки — до выбранной целевой доли. Обработка выполняется при импорте или кнопкой «Обработать обязательства». Совместимые инвойсы объединяются по дате и фиксингу. Для изменения исполненного хеджа создаётся запрос на пересмотр.

Локально сохраняется имя приложения к обращению. Содержимое файла на сервер не загружается. Готовность реальных соглашений и прав подписанта предполагается для демо. Производственная интеграция потребует банковской аутентификации, серверной обработки, управления полномочиями, котирования и журналирования.

Концепция опирается на командные документы в родительской папке. Внешние интеграции, тарифы и преимущества не заявляются как уже действующие услуги БСПБ.

## Границы текущей версии

Реализован расчётный форвард для обязательства в RUB с привязкой к CNY. Опционы трека Б, кредитный пакет и SCF из новых наработок команды не реализованы. При оплате поставщику в CNY кабинет направляет условия хеджирования менеджеру; отдельная демонстрационная конвертация доступна.

Политика, минимумы и лимит относятся к учебной модели. Демо-исполнение хеджа не меняет статус оплаты поставщику.

## Проверка

Проверены сборка TypeScript/Vite, доменные расчёты и полный браузерный маршрут: политика, автоматическая демо-сделка, повтор ERP, пересмотр даты, обращение, обмен, импорт с дублями, сохранение после перезагрузки, CSV и печать, мобильная ширина. Скриншоты и результат — в `qa/`. Браузерный скрипт использует локальный Chromium и окружение этой машины; для переноса нужно настроить пути в `qa/browser-check.cjs`.
